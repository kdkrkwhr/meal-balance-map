# 제품 기획과 MVP

[문서 홈](../README.md) · 기준일 2026-11-09

## 목적과 사용자

누구나 일상에서 균형 잡힌 외식을 고르도록 돕습니다. 일반 맛집 지도에서 인기·거리로 식당을 찾은 뒤 메뉴와 식사 구성을 다시 조사해야 하는 불편을 줄이는 것이 목적입니다. 운동 인구, 체중 감량이나 치료 식단에 한정하지 않습니다.

식당의 결제 기반 인기도와 메뉴의 영양 참고 평가를 구분합니다. ‘건강한 식당 순위’를 단정하지 않고 사용자의 선호와 확인 가능한 근거를 함께 보여줍니다.

## 대표 사용자 흐름

1. **지역 선택:** 지역 검색을 기본으로 하고, 현재 위치는 별도 동의를 받은 경우에 사용합니다.
2. **탐색:** 지도 핀·목록에 식당과 실제 메뉴 자료 보유 여부를 표시합니다.
3. **선호 입력:** 채소 포함, 따뜻한 음식 등 조건 버튼을 제공합니다. 자연어는 개인정보 처리 조건을 충족한 범위에서 지원합니다.
4. **메뉴 비교:** 조건에 맞는 확인된 메뉴 후보 최대 세 개를 비교합니다. 후보가 적으면 억지로 채우지 않습니다.
5. **근거 확인:** 영양 기준량·출처·확인 수준, 매칭 사유와 Wiki/Graph 관계를 확인합니다.
6. **상세 이동:** 응답받은 잇플 상세 URL로 이동합니다. 실제 예약·결제는 하지 않습니다.

## 지도와 상세 카드

- 지도: 식당명, 메뉴 데이터 유무, 선택한 지역을 표시합니다. 정확한 사용자 위치를 장기 보관하지 않습니다.
- 메뉴 카드: 실제 메뉴명, 메뉴 출처와 확인일, 연결한 음식코드·기준량, 이용 가능한 영양값을 보여줍니다.
- 설명: ‘식약처 유사 음식 기준 참고값 · 해당 식당 실측 아님’을 매칭 결과 근처에 표시합니다.
- 비교: 양·단위가 다른 메뉴의 숫자를 동일 조건인 것처럼 순위화하지 않습니다.
- 정보 부족: 실제 메뉴가 없으면 식당 정보만 보여주고 메뉴명이나 영양 수치를 생성하지 않습니다.
- 기본 추천은 설명형입니다. 점수 도입은 기준·가중치·누락 처리·버전 검증 후 별도 결정합니다.

예시 문구: **‘돌솥비빔밥: 채소와 곡류가 포함되는 메뉴 후보. 단백질 구성과 소스·밥의 양은 확인이 필요합니다.’** 실제 자료가 없는 영양 숫자는 예시에 넣지 않습니다.

## MVP와 제출판

| 단계 | 포함할 기능 |
| --- | --- |
| 기본 지도 MVP | 한 지역, 검수된 메뉴, 잇플 식당 검색, 지도/목록, 식약처 유사 음식 매칭, 계산 skill, 출처와 기준량, 잇플 상세 이동 |
| 제출판 필수 | AI 메뉴 매칭 후보·추천 이유, 선호 입력, 근거 Wiki, Graphify 관계 탐색, 비용 제한과 장애 시 축소 동작 |
| 후속 검토 | 지역 확대, 식사 기록, 이미지 인식, 실시간 메뉴 자동 수집 |

한 지역으로 제한하는 것은 제안이며 지역·식당 수는 아직 정하지 않았습니다. Wiki/Graphify는 단순 장식이나 정확도 보증이 아니라 추천 근거를 확인하는 기능입니다.

## 범위 밖

질환별 치료식 처방, 알레르기 안전 보장, 식당 실측 영양이라고 표시하기, 체중 목표·하루 섭취량 추적, 계정·사진 업로드·예약·결제·리뷰 작성은 초기 범위에서 제외합니다.

## 성공 지표

- 검색 성공률과 실제 메뉴 정보 커버리지
- 검수 샘플의 매칭 통과·오류·보류율
- 메뉴 카드·근거 패널 열람 및 잇플 상세 이동률
- 무료 한도 소진 시 비용 발생 없이 대체 흐름으로 이어지는 비율

목표 수치는 초기 검증 뒤 정합니다. 자체 클릭 수를 공모전에서 인정하는 활성 사용자 수로 간주하지 않습니다. 공식 집계·중복 제외·전환 추적 기준은 [미확인 사항](decisions-and-open-questions.md)에 남깁니다.
