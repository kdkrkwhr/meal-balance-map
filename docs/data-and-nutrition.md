# 데이터와 영양 평가 정책

[문서 홈](../README.md) · 자료 확인 기준 2026-11-09

## 데이터 원천

| 원천 | 활용 | 아직 해결할 점 |
| --- | --- | --- |
| 잇플 | 식당명·주소·업종·좌표·상세 URL, 최근 한 달 결제 기반 집계 지표 | 발급·호출 한도·캐시/재배포·공모전 전환 추적 |
| 공식 메뉴 또는 식당 제공 자료 | 해당 식당의 실제 판매 메뉴 연결 | 출처별 사용 허가·확인일·갱신·품절 대응 |
| 식약처 음식 DB | 음식코드·분류·기준량·영양값·출처·기준일 | 다운로드/API 조건, 필드·단위·누락값 처리 |

잇플 문서에서 메뉴명·가격·재료·영양성분 필드는 확인되지 않았습니다. 따라서 메뉴 연결은 별도 데이터 작업입니다. 타 플랫폼의 이미지나 메뉴를 무단으로 복제하지 않습니다.

## 잇플 연동 시 확인한 제약

- 공개 정의서의 직접 검색은 `POST https://api.paybooc.ai/api/mer/v1/search`입니다.
- 기관정보와 요청 추적번호, 주소·상호·업종 조건 등을 사용합니다. 정확한 필드·인증은 발급 후 재확인합니다.
- 주소 텍스트 검색이며 반경 검색이 아닙니다. 최대 100건·페이징 없음으로 안내됩니다.
- 지도 좌표는 TM128이며 SDK에 따라 WGS84 등 변환이 필요합니다. 좌표 변환 정확성을 별도 시험합니다.
- `merUrl`은 응답값을 그대로 사용합니다. 앱 내부용 키워드 검색 경로를 승인 없이 파트너용으로 사용하지 않습니다.
- 매출 백분위는 맛·건강 점수가 아닙니다. 영업시간은 예상 정보로 실제 영업 여부를 보장하지 않습니다.
- 요청 추적번호를 공모전 활성 사용자 추적 ID로 취급하지 않습니다.

이 문서는 실제 API 호출·계약 체결을 의미하지 않습니다.

## 제안 데이터 모델

다음은 내부 모델 제안이며 외부 API의 실제 필드 정의가 아닙니다.

| 엔터티 | 최소 정보 |
| --- | --- |
| RestaurantReference | 공급자 식별 참조, 이름, 위치 좌표계, 상세 URL, 확인일, 저장 허가 상태 |
| VerifiedMenu | 식당 참조, 메뉴명, 확인된 설명, 출처·권리 근거·확인일, 판매 확인 상태 |
| FoodReference | 식약처 음식코드·분류, 영양값·단위·기준량, 출처·데이터 버전 |
| MenuFoodMatch | 메뉴와 음식코드, 매칭 근거, 검토 상태, 알려진 양/조리법 차이, 검토일 |
| Recommendation | 적용 선호, 근거 참조, 계산 버전, 설명, 정보 부족 경고 |

잇플 데이터의 영구 저장 허가가 확인되지 않았다면 RestaurantReference도 허용 범위 안에서만 유지합니다. 참조 모델이 저장 권한을 만들어주지는 않습니다.

## 매칭·계산 절차

1. 실제 메뉴명·설명을 확보하고 재료·조리법의 확인 정보와 추정을 구분합니다.
2. 식약처의 **음식 DB**에서 유사 후보를 찾습니다. 가공식품·원재료와 혼동하지 않습니다.
3. AI는 후보와 사유를 제안합니다. 이름이 같아도 브랜드·조리법·구성이 다르면 확정하지 않습니다.
4. 검토 가능한 항목만 연결하고 애매한 후보는 `검토 필요`로 유지합니다.
5. 영양값은 데이터에서 읽습니다. 같은 단위의 제공량이 확인된 경우에만 `기준 영양값 × 제공량 ÷ 함량 기준량`으로 환산합니다.
6. 양이 모르면 DB 기준량 그대로 표시합니다. 임의로 1인분이나 100g으로 취급하지 않습니다. 질량·부피 변환도 근거 없이 하지 않습니다.
7. 누락값은 미확인으로 보존합니다. 누락을 0으로 채우거나 잘못된 단위를 조용히 보정하지 않습니다.

## 정보 수준과 사용자 표시

- **식당 제공 수치:** 출처·기준량·확인일을 표시합니다. 독립 실측 검증이라고 주장하지 않습니다.
- **검토된 유사 음식:** ‘식약처 유사 음식 기준 참고값 · 해당 식당 실측 아님’을 표시합니다.
- **메뉴명만 확인:** 설명형 후보로만 보여주고 실제 양·레시피가 불명임을 알립니다.
- **평가 불가:** 항목 또는 기준량이 충분하지 않으면 영양 비교를 보류합니다.

AI의 자기 확신도를 정확도나 신뢰도 수치로 표시하지 않습니다. 자료 수준은 확인한 출처와 검수 상태로 정합니다.

## 균형 평가

초기에는 검수된 태그로 채소·단백질원·곡류 구성을 설명하고, 비교 가능한 영양값을 함께 제시합니다. 단일 영양소만으로 모든 메뉴의 우열을 단정하지 않습니다. 질환·알레르기별 안전 판단을 대신하지 않습니다.

숫자 점수는 아직 미확정입니다. 도입하려면 서비스 자체 기준·가중치·적용 대상·버전·누락 처리와 검증 샘플을 공개하고, ‘식약처 공식 점수’라고 표현하지 않습니다.

## 변경 관리

원천 버전, 메뉴 확인일, 매칭 변경 이유와 계산 버전을 추적합니다. 원천 데이터가 바뀌면 영향을 받는 매칭을 재검토합니다. AI가 자동으로 이전 검수 결과를 덮어쓰지 않습니다. 업데이트 주기·최소 검수 표본은 초기 데이터 확보 단계에서 정합니다.
